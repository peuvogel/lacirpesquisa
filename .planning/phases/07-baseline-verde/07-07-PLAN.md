<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| runner do GitHub Actions ← Actions de terceiros | `actions/checkout` e `actions/setup-node` executam com acesso ao checkout e ao ambiente do job |
| git local ← `core.hooksPath` | Scripts do repositório passam a executar automaticamente em cada commit/push do desenvolvedor |
| desenvolvedor → histórico | `--no-verify` bypassa qualquer hook local; é comportamento padrão do git, não um defeito desta implementação |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-07-07-01 | Tampering | `.github/workflows/ci.yml` (supply chain) | mitigate | Fixar `actions/checkout@v7` e `actions/setup-node@v7` por tag major da organização `actions` (primeira-parte GitHub, tags confirmadas via API na pesquisa); critério de aceite proíbe `@main`/`@master`. Pin por SHA fica como endurecimento futuro, desproporcional ao risco atual (sem segredos de produção no bundle) |
| T-07-07-02 | Tampering | `.githooks/*` executados por `core.hooksPath` | mitigate | `core.hooksPath` aponta só para `.githooks/` **dentro** do repositório versionado — nenhum hook externo é executado; o script `prepare` que faz o bootstrap é uma linha auditável no `package.json` |
| T-07-07-03 | Repudiation | gate local | accept | `--no-verify` bypassa `pre-commit`/`pre-push` — bypass conhecido e documentado do git, impossível de fechar localmente. | T-07-07-04 | Repudiation | gate local (inércia silenciosa) | mitigate | Três modos de inércia verificados na pesquisa (clone sem `npm install`, `core.hooksPath` para diretório inexistente, bit executável perdido) — mitigados pelo script `prepare`, pelo critério que confere `git config core.hooksPath`, e pelo critério que confere modo `100755` no índice |
