<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| app → external official portals | Collection links navigate the user to third-party government sites |
| pasted text inside the modal → session → another route | Untrusted input crosses a route boundary via shared session state |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-TAB | Spoofing | Collection links opening new tabs | mitigate | Every external link uses `rel="noopener noreferrer"` with `target="_blank"`, asserted in the modal test |
| T-01-XSS | Tampering | Modal rendering pasted rows and variable names | mitigate | The paste step reuses plan 01-06's `TabularInputPanel`, which renders parsed values as JSX text children and is already covered by a DOM-level XSS assertion; no HTML is constructed in this plan |
| T-01-URL | Tampering | Fabricated or attacker-influenced link URLs | mitigate | Links come from a committed static map of official portal base URLs — no URL is derived from user input or remote data, so there is no injection path into `href` |
| T-01-MOCK | Repudiation | Mock suggestions/availability mistaken for real guidance | mitigate | A visible stub notice heads the modal and every suggestion carries an explicit status badge; the didactic risk is closed when Phase 4/5 supply real data |
</threat_model>
