<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| URL / history → router | User-controlled path strings select which route element renders |
| session context → all routes | In-memory user data crosses route boundaries within the tab |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-ROUTE | Denial of Service | Unhandled render error blanking the SPA | mitigate | Root route declares an `errorElement` with a Portuguese fallback and a link back to `/`, so one broken route cannot take down the portal |
| T-01-XSS3 | Tampering | Route/nav labels and empty-state copy | mitigate | All shell copy is static literals rendered as JSX text children; no `dangerouslySetInnerHTML` anywhere in the shell, and no user input reaches the header or placeholders |
| T-01-PRIV | Information Disclosure | Session data persisting past the browsing session | mitigate | `SessionProvider` writes to no storage API (asserted by the Task 1 spy test), so pasted health data never outlives the tab — matching the milestone's no-persistence stance |
| T-01-OPEN | Spoofing | Open-redirect style navigation | accept | Routing is limited to four hardcoded internal paths with no dynamic redirect targets, so there is nothing to redirect to |
</threat_model>
