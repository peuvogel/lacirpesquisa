<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| CDN → browser runtime | v1.0 imported Chart.js from jsdelivr at runtime; this plan removes that boundary entirely |
| chart data → canvas render | User-derived numbers and labels reach Chart.js, which draws them as canvas pixels (not HTML) |
| canvas → local filesystem | PNG export writes a file to the user's machine via a synthetic anchor download |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-CDN | Tampering | Chart.js module resolution | mitigate | `ChartCanvas` imports from the bare `'chart.js'` specifier so Vite bundles the lockfile-pinned dependency; enforced by the `cdn.jsdelivr.net` absence gate in Task 2's verify (01-RESEARCH.md Pitfall 6) |
| T-01-XSS2 | Tampering | User-supplied labels rendered in chart tooltips/axes | mitigate | Chart.js draws text onto a canvas rather than injecting HTML, so pasted content cannot become markup here; `ChartCanvas` passes data straight through and never builds HTML strings |
| T-01-DL | Information Disclosure | PNG export writing to the local filesystem | accept | The download contains only data the user themselves pasted, stays on their machine, and uses a user-initiated click; no cross-origin or network transmission is involved |
| T-01-MEM | Denial of Service | `toDataURL` on a very large canvas | accept | Chart canvases are viewport-sized with a fixed aspect ratio, bounding the data URL; a slow export on a huge display degrades UX only, with no security impact |
</threat_model>
