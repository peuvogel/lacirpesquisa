<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| imported DataSUS files/text → wizard state | Multiple untrusted sources are held simultaneously and re-parsed on every correction |
| wizard state → JSX render | Header labels, cell samples, and file names all render into the DOM |
| confirmed session → cross-route consumers | The published session becomes input for tests in later phases |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-XSS | Tampering | Every wizard step rendering source-derived strings | mitigate | The legacy `render()`/`innerHTML` layer is explicitly not ported; all values render as JSX text children, enforced by a per-directory absence gate on `dangerouslySetInnerHTML`/`escapeHtml` plus a DOM-level `<script>`-payload test |
| T-01-DoS | Denial of Service | `addFiles` on an unreadable/corrupt source | mitigate | Per-file try/catch sets an `error`-tone status and preserves previously imported sources, so one bad file cannot empty the wizard or crash the route |
| T-01-STATE | Tampering | Stale `confirmed` flag after a mapping change | mitigate | Every mapping mutation clears `confirmed` and re-normalizes (ported behavior), so a downstream consumer can never receive a session confirmed against an older mapping |
| T-01-PROTO | Tampering | Mapping objects keyed by user-supplied header names | accept | Plain data objects in a client-only app with no prototype-sensitive lookups and no privilege boundary; same disposition as plan 01-03 |
</threat_model>
