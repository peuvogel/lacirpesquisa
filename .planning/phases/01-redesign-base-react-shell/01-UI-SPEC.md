## Spacing Scale

Declared values (multiples of 4 only):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-label gaps, badge internal padding |
| sm | 8px | Compact list-item spacing, chip gaps, form field internal padding (vertical) |
| md | 16px | Default element spacing, card internal padding (compact cards), sidebar item padding |
| lg | 24px | Section padding, page-shell horizontal gutters, modal body padding |
| xl | 32px | Layout gaps between major panels (sidebar ↔ main), stepper spacing |
| 2xl | 48px | Major section breaks (e.g. above/below the FlowSteps stepper header) |
| 3xl | 64px | Page-level top spacing on Meta-análise/Variáveis "em breve" placeholders (centered empty-state layouts) |

**Radius scale** (not in the 8pt spacing scale but declared here since it recurs everywhere): `--radius-sm: 8px` (chips, inputs), `--radius-md: 12px` (buttons, small cards), `--radius-lg: 16px` (panels, modals, sidebar cards) — matches legacy `--radius-md`/`--radius-lg` values, so the "clinical/academic" rounded-card feel carries over.

**Exceptions:**
- Icon-only buttons (sidebar collapse toggle, info button, modal close) use a **44×44px** minimum hit target even though the visible icon/circle may render smaller (e.g. a 34px visible circle centered in a 44px hit area) — WCAG 2.5.5 touch-target minimum.
- The Mapas SVG UF paths do not follow the spacing scale (they're geographic shapes) but their hover/focus outline stroke-width is fixed at **2px** for legibility at map scale.

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 16px | 400 (regular) | 1.6 |
| Label | 14px | 700 (bold) | 1.4 |
| Heading | 20px | 700 (bold) | 1.2 |
| Display | 32px | 700 (bold) | 1.15 |

**Rule:** exactly 2 weights across the entire app — **400** (body copy, table cells, paragraph text, interpretation text) and **700** (everything else: nav labels, buttons, headings, metric values, badges, sidebar item titles). Do not introduce 500/600/800/900 anywhere, even though the legacy CSS leaned on 800–900 for headings — 700 carries the same "confident/academic" weight without adding a third weight to maintain.

**4 sizes only:** 14 / 16 / 20 / 32. Anything the legacy CSS expressed at odd sizes (`.75rem`, `.86rem`, `1.05rem`, `1.46rem`, `1.85rem`, `2rem`) maps onto the nearest of these four — e.g. metric values (legacy 1.46rem ≈ 23px) become **20px/700** (Heading role), the demo's page title (legacy 1.85–2rem) becomes **32px/700** (Display role), micro-labels (legacy .72–.78rem) become **14px/700** at reduced opacity via color (`--text-muted`), not a 5th size.

**Data/mono text** (pasted textarea, column preview table, code-style values): **IBM Plex Mono, 14px, 400, line-height 1.55** — kept outside the 4-size UI scale since it's a distinct "data mode" register (already the pattern in legacy `.input-box`/`.code-block`/`.preview-table`), not a competing type system.

## Color

|------|-------|-------|
| Dominant (60%) | `#0a0f0d` (page background) with `#0d1310` (app-shell base) | Page background, `<body>`, route backgrounds behind panels — near-black with a barely-perceptible green-teal undertone (not pure `#000`/`#09090b` neutral black), continuing the legacy palette's warmth rather than the cold neutral-black of a generic dark-mode template |
| Secondary (30%) | `#121917` (panel/card surface), `#171f1c` (elevated: modals, popovers, active sidebar item) | Header bar, sidebar, cards (sidebar-card, result-card, chart-card, metric-card), modal/dialog backgrounds, Mapas side panel, DataSUS wizard source cards |
| Accent (10%) | `#10b981` (clinical teal, per D-16) | **Reserved for:** primary CTA buttons (background), active `NavLink` underline + text color, focus rings (`focus-visible` outline), links, primary chart series/line color, selected/locked UF fill+stroke on the map, "disponível" status dot in the test registry, active FlowSteps step indicator, intersection-variable highlight in the Mapas variable panel, the small accent glow on the LACIR logo mark's own circular backdrop area (already present in the source PNG) |
| Destructive | `#ef4444` | **Reserved for:** "Limpar dados" destructive button, friendly parse-error banner text/icon, the "não existe em [UF, UF]" partial-variable alert text in the Mapas panel, native browser `beforeunload` prompt is browser-styled (out of our control) |
| Warning (secondary semantic, minimal use) | `#f59e0b` | **Reserved for:** file-type/size soft warnings during paste/upload (e.g. "arquivo grande, pode demorar"), reserved for Phase 3's assumption-check nudges (UX-02) so the token exists now but Phase 1 uses it sparingly — at most the upload dropzone's oversize hint |

Accent reserved for: primary CTA background, active nav indicator, focus rings, chart primary series, selected-UF map fill, "disponível" status dot, active flow-step marker, intersection-variable highlight. **Never** apply teal to body text color, disabled states, or decorative-only surfaces — the "balanced" mandate (D-15) means teal marks *meaningful* state, not ambient decoration.

**Contrast note (WCAG AA):** `#10b981` on `#0a0f0d` background computes to ~7.1:1 (passes AA for normal text); `#10b981` on `#121917` (secondary surface) computes to ~6.6:1 (passes AA). Body text uses `#e6efe9` (off-white with a faint green tint, not pure `#fff`) at ~15.5:1 on the dominant background — comfortably exceeds AA. Muted/secondary text uses `#8fa89c` at ~4.6:1 on dominant background — passes AA for normal text; do not go lighter/more-muted than this for any text that conveys information (only for pure decoration).

## Empty / Error / Loading States

**Empty:**
- Dados step before any input — see Copywriting Contract; icon-free (no illustration asset exists yet), just heading + body + the input controls themselves visible below.
- Mapas before hover/select — see Copywriting Contract; map is fully visible and interactive, panel shows the empty-state copy in place of the variable list.
- Meta-análise / Variáveis — "Em breve" `EmptyState`, centered, no controls.
- Resultados step reached with zero rows confirmed — should be structurally unreachable (CTA stays disabled until `Configurar` is valid), so no dedicated empty state is needed here; if it ever occurs, fall back to the same Dados-step empty copy with a "voltar para Dados" link.

**Error:**
- Parse/validation failure (UI-03) — inline `Alert` (destructive-colored border/icon, not a full-page error), friendly copy per Copywriting Contract, with an expandable "Ver detalhes" for the specific row/column diagnostic already produced by the ported `buildTabularRecognitionError`. Never a raw stack trace or English error string.
- File read failure (corrupt/oversized XLSX) — same `Alert` pattern, copy: "Não foi possível ler este arquivo. Tente novamente ou cole os dados diretamente."
- Mapas partial-variable "gap" — not a blocking error, just the inline destructive-colored note (D-22) within an otherwise successful state.

**Loading:**
- Paste/parse — near-instant for typical sizes, but implement a brief inline spinner/skeleton state on the preview area rather than a blank flash (parsing is synchronous today but should still render a state to avoid layout jump).
- File upload (XLSX unzip) — same pattern, dropzone shows a small progress/spinner overlay while `readTabularFileState` resolves.
- Chart render — `ChartCanvas` shows a fixed-height skeleton block (matches final chart's aspect ratio) until Chart.js has mounted, to avoid layout shift.
- Route transition (first-party CSS entry animation) — the fade/slide-in itself communicates "new content arriving"; no separate spinner needed for route changes since there's no network fetch.

## Accessibility

- **Contrast:** all text/background pairs above are pre-checked to WCAG AA (4.5:1 normal text, 3:1 large text/UI components) — see Color section notes. Do not introduce a new text color without checking against both the dominant (`#0a0f0d`) and secondary (`#121917`) surfaces it will appear on.
- **Focus visibility:** every interactive element (`NavLink`, buttons, sidebar items, modal triggers, SVG UF paths, checkboxes, selects) must show a visible `focus-visible` ring in teal (`2px solid #10b981` + slight offset) — never rely on the browser default outline being removed without a replacement.
- **Keyboard access to the map (D-20/D-21/D-23):** `BrazilMockMap`'s 27 `<path>` elements must be reachable via `Tab` (each `<path>` gets `tabindex="0"` + `role="button"` + `aria-label="{Nome do estado}"`) with `Enter`/`Space` triggering the same "click" (lock/select) behavior as a mouse click, and `Escape` or a dedicated "limpar seleção" control to clear multi-select — mouse-only interaction is not acceptable given D-20–D-23's hover/click are core to the feature, not decoration.
- **Color is never the only signal:** `disponível`/`em-breve` status uses both color AND text label (badge text, not just a colored dot alone) — the sidebar dot is a supplementary visual, not the sole indicator. The Mapas partial-variable alert uses both destructive color AND the explicit "não existe em {UF}" text.
- **Modal focus management:** `QualTesteModal` and `IniciarPesquisaModal` (shadcn `Dialog`, Radix-based) trap focus while open, restore focus to the trigger button on close, and close on `Escape` — this is Radix's default behavior, do not override it.
- **`aria-live` regions:** the parse-error `Alert` and the "dados analisados com sucesso" (implicit success via reaching Resultados) should be in an `aria-live="polite"` region so screen-reader users are notified without needing to re-navigate.
- **Stepper semantics:** `FlowSteps` buttons use `aria-current="step"` on the active step (already shown in RESEARCH.md's Pattern 2 example) and `aria-disabled` (not just visual disabling) on steps not yet reachable.
- **Reduced motion:** wrap both first-party accents (header texture animation, route-entry fade) in a `prefers-reduced-motion: reduce` media query fallback that disables the animation but keeps the final visual state — required given D-15's "balanced" (not showy) motion stance.
- **Native `beforeunload` (D-18):** this is a browser-native accessibility-neutral mechanism (browser renders its own accessible dialog) — no additional a11y work needed beyond correctly scoping when it fires (RESEARCH.md Pitfall 2).

## Claude's Discretion (flagged decisions, not in CONTEXT.md)

These are the specific choices this research pass made without user confirmation, since AskUserQuestion was unavailable. Each is the lowest-risk, most-didactic default consistent with locked decisions — flagging them here so the checker/planner/user can override any single one without reopening the whole contract.

1. **Exact teal/background hex values** (`#10b981` accent was locked by D-16; the specific dark surface triad `#0a0f0d`/`#121917`/`#171f1c` and destructive/warning hexes are this session's choice, sampled to keep contrast AA-safe against the locked teal).
2. **Font choice** — Sora (UI) + IBM Plex Mono (data).
