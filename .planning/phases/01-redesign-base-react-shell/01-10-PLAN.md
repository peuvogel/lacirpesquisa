<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| confirmed dataset → chart + interpretation | User-pasted values flow into computed prose and canvas rendering |
| generated interpretation → DOM | Strings built from user data are rendered as page content |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-XSS | Tampering | `InterpretationText`, metric cards, chart labels | mitigate | Interpretation paragraphs and metric values render as JSX text children with no markdown/HTML parsing; a DOM-level test asserts an embedded `<b>` payload stays inert; chart labels are drawn to canvas, not injected as markup |
| T-01-STAT | Repudiation | A stub presenting descriptive numbers in a teaching tool | mitigate | `buildDemoInterpretation` states plainly that the demo only describes the data, and a test forbids `p =` / `p-valor` / `IC` substrings so the stub cannot silently imply inferential results before Phase 2 ports the real engines |
| T-01-DoS | Denial of Service | A very large confirmed dataset rendered as metrics/chart | accept | Preview rows are capped by `ColumnPreviewTable` and Chart.js aggregates to a handful of bars; a slow render on an enormous paste degrades UX only, entirely within the user's own tab |
| T-01-DL | Information Disclosure | PNG export of user data | accept | Same disposition as plan 01-04: user-initiated, local-only, contains only data the user supplied |
</threat_model>
